# Multishop — этап 2а «Подключение аккаунтов OLX и eBay»: план

**Spec:** `docs/superpowers/specs/2026-11-11-multishop-design.md`, «Дополнение 2026-11-12:
подключение аккаунтов».

1. **OAuth-шов** (`convex/lib/oauth.ts`): провайдеры OLX и eBay — ссылка входа, обмен кода на
   токены, конфиг из переменных. Ошибки без токенов и секретов. Тесты на запросы.
2. **Страницы** (`convex/lib/pages.ts`): политика конфиденциальности, «подключено»,
   «не получилось». Экранирование. Тесты.
3. **Данные**: таблицы `oauthStates` (state, provider, chatId) и `accounts`
   (provider, токены, сроки).
4. **Логика** (`convex/accounts.ts`): `show` (статус + кнопки-ссылки), `newState`,
   `consumeState` (одноразово, 15 минут), `save`, `complete` (весь возврат). Тесты.
5. **Бот и HTTP**: кнопка меню «🔗 Аккаунты», `/accounts`, кнопки-ссылки в Telegram, маршруты
   `/privacy`, `/oauth/{olx,ebay}/callback`, `/oauth/ebay/declined`. Тесты.
6. Деплой, `telegram:setWebhook` (меню команд), `OLX_CLIENT_ID=6005`, ревью, итог.

## Итог выполнения (2026-11-12)

Сделаны шаги 1–6. Результат: 277 тестов, линт, типы проходят. Загружено в dev,
`OLX_CLIENT_ID=6005` задан, меню команд обновлено. `/privacy` отвечает 200, callback с
неизвестным state — страница «Ссылка устарела» (400).

Исправлено по независимому ревью:
- Ошибка сохранения доступа не попадает ни в бот, ни на страницу, ни в лог (ошибки Convex
  цитируют аргументы, то есть токены). Показываются только ошибки обмена кода, собранные без
  секретов.
- Ошибка площадки, кроме `access_denied`, показывается как ошибка с её кодом, а не как
  «отменено».
- Политика конфиденциальности описывает только то, что есть: отзыв доступа в настройках
  площадки, удаление в базе.
- Если `/accounts` упал, владелец получает сообщение.
- `HTTP 502` в тексте ошибки сохраняет пробел.
- Добавлены тесты: успешный HTTP-callback с обрезкой до 2048, eBay с RuName, сгорание state при
  чужом провайдере, ошибка сохранения.

Ещё не проверено вживую: настоящий вход OLX (ждём `OLX_CLIENT_SECRET`) и eBay (ждём ключи).
Отложено: обновление токенов по refresh token — понадобится на этапе публикации.
