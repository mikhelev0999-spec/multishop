# Multishop — этап 1б «Фотостудия»: план реализации

**Goal:** Кнопка «🎨 Обработать фото» под черновиком открывает в Telegram мини-приложение, которое
на телефоне владельца убирает фон, ставит однотонный фон, центрирует вещь и слегка улучшает
свет и резкость. Результат сохраняется в Convex, бот присылает его в чат, а «Выставить»
присылает альбом фото в порядке для объявления.

**Architecture:** Страница `/studio` в существующем Vite-приложении. Удаление фона —
`@imgly/background-removal` в браузере (WASM, модель качается с CDN imgly при первом
запуске). Композиция и коррекция — Canvas 2D, чистые функции над `ImageData`. Связь с Convex —
публичные actions `studio.*`; каждая проверяет `initData` Telegram (HMAC-SHA256 через
WebCrypto). Загрузка — через `ctx.storage.generateUploadUrl()`.

**Spec:** `docs/superpowers/specs/2026-11-11-multishop-design.md`, «Дополнение 2026-11-12».

## Global Constraints

- Бесплатно: никаких платных API.
- Ни одна функция `studio.*` не работает без проверенного `initData` владельца.
- Компоненты не ходят в Convex напрямую — только через `src/lib/studioApi.ts`.
- Тексты страницы — на русском.
- Тесты до кода; перед коммитом отдельно `npm test`, `npm run lint`, `npm run typecheck`.

### Task 1: Проверка initData

`verifyInitData(initData, botToken, nowSec, maxAgeSec)` → `{ userId }` или ошибка.
- `data_check_string`: пары `key=value` без `hash`, отсортированы по ключу, через `\n`.
- `secret = HMAC_SHA256(key="WebAppData", msg=botToken)`;
  `hash == hex(HMAC_SHA256(key=secret, msg=data_check_string))`, сравнение за постоянное время.
- `auth_date` не старше 24 часов; `user.id` из JSON-поля `user`.
- Тесты: подпись, посчитанная в тесте тем же алгоритмом, проходит; подменённое поле, чужой
  токен, просроченный `auth_date`, нет `hash`, нет `user` — ошибки.

### Task 2: Функции студии в Convex

- `studio.load({ initData, itemId })` → `{ title, photos: [{ storageId, url }], studio: [...] }`
  для вещи владельца в статусе `draft`.
- `studio.uploadUrls({ initData, itemId, count ≤ 10 })` → одноразовые URL загрузки.
- `studio.save({ initData, itemId, storageIds })` → записывает `studioPhotoIds` (заменяя
  прежние и удаляя их файлы), бот присылает новые фото альбомом.
- Проверка, что `storageIds` — картинки не больше 5 МБ (`ctx.storage.getMetadata`), иначе
  файлы удаляются и возвращается ошибка.
- Тесты: без `initData` / с чужим ID — отказ; полный цикл load → save; повторное сохранение
  удаляет старые файлы; лишний или большой файл отклоняется.

### Task 3: Бот

- `Button` получает вариант `{ text, webAppUrl }`; `telegramApi` отдаёт `web_app: { url }`.
- Клавиатура черновика: третья строка «🎨 Обработать фото» с
  `${STUDIO_URL}/studio?item=<id>`, только если `STUDIO_URL` задан.
- `sendMediaGroup(chatId, urls)` (до 10 фото).
- «Выставить»: после текста — альбом фото в порядке: студийные, затем оригиналы (не больше 10).
- Тесты: клавиатура с адресом и без; порядок фото; `sendMediaGroup` формирует запрос.

### Task 4: Обработка изображений (чистые функции)

- `autoLevels(data)`: растяжение по каналам с отсечкой 0,5% теней и светов.
- `sharpen(data, w, h, amount)`: unsharp mask 3×3, по умолчанию слабый.
- `fitBox(objW, objH, canvasSize, padding)`: размер и положение вещи на квадратном холсте
  1600×1600 с полями 8%.
- `alphaBounds(data, w, h)`: рамка непрозрачных пикселей после удаления фона.
- Тесты на маленьких массивах.

### Task 5: Страница студии

- `/studio?item=<id>`: читает `initData` из `window.Telegram.WebApp`; вне Telegram —
  «Откройте из бота».
- Сетка фото с галочками (по умолчанию первое), выбор фона: белый, светло-серый, бежевый,
  чёрный, свой цвет.
- «Обработать»: для каждого отмеченного — удаление фона (шов), обрезка по `alphaBounds`,
  композиция на холсте с фоном и мягкой тенью, `autoLevels`, `sharpen`, JPEG 0,9.
  Прогресс «Фото 2 из 3…»; первый запуск предупреждает о скачивании модели.
- Просмотр до/после, «Сохранить» → `uploadUrls` → загрузка → `save` → «Готово, фото в чате» и
  закрытие мини-приложения.
- Тесты (jsdom, швы замоканы): вне Telegram; загрузка и показ фото; обработка вызывает шов
  для отмеченных; сохранение отправляет нужные storageIds; ошибка показывается текстом.

### Task 6: Публикация страницы

- `README`: `STUDIO_URL` в Convex, деплой на Vercel (`VITE_CONVEX_URL` в env Vercel).
- Первый деплой запускает владелец; после него — `STUDIO_URL` в Convex и проверка в боте.

## Критерии завершения

- Все проверки зелёные; `studio.*` отказывает без подписи владельца.
- В боте под черновиком кнопка студии; на телефоне фото обрабатывается и приходит в чат.
- «Выставить» присылает текст и альбом фото.

## Итог выполнения (2026-11-12)

Задачи 1–5 выполнены, серверная часть загружена в dev-деплоймент Convex: 170 тестов, линт,
типы и сборка проходят. Склейка фото проверена в настоящем Chromium: квадрат 1600×1600,
нужный фон, вещь по центру. **Не проверено:**
- нейросеть удаления фона (CDN модели закрыт из среды разработки);
- CORS при скачивании фото из хранилища Convex на странице Vercel;
- работа в Telegram на телефоне.

Задача 6 (публикация на Vercel) ждёт владельца.

Отклонения от плана:
- Размер проверяется по метаданным `_storage`, тип — по сигнатуре файла: тестовая среда
  Convex не хранит `contentType`, и заявленному типу верить нельзя. Принимается только JPEG
  (страница всегда отдаёт JPEG; WebP Telegram в альбоме не любит).
- Подпись Telegram для студии действует 2 часа, а не сутки.
- Повторное сохранение не заменяет список молча: страница показывает уже обработанные фото,
  владелец снимает галочки с тех, что нужно удалить.

Исправлено по независимому ревью:
- **Владельцы файлов.** Таблица `storageOwners` (оригинал или студийное фото, какой вещи).
  `save` берёт только свежие ничьи загрузки или студийные фото этой же вещи, а при ошибке
  удаляет только свежие загрузки. Чужие файлы не трогаются.
- **Очистка.** Раз в час удаляются ничьи файлы старше часа (`files.pruneOrphans`).
  `files.backfillOwners` один раз запущен на dev. «Отмена» удаляет студийные фото.
- **Альбомы.** Если альбом не отправился, бот пишет об этом. В альбоме «Выставить» до пяти
  оригиналов всегда остаются.
- **Кнопка студии** только при `https`-адресе (иначе Telegram отклонил бы весь черновик).
- **Страница.** Свой цвет применяется через 300 мс после последнего выбора, и результат
  берётся только от последнего выбора. Холсты освобождаются, object URL отзываются. Прогресс
  показывается только во время загрузки модели.

Лицензия `@imgly/background-removal` — AGPL. Для страницы, которой пользуется только
владелец, это не ограничение. Если студия станет сервисом для других людей, понадобится
открыть код или взять коммерческую лицензию imgly.

## Дополнение 2026-11-12: настройки качества

По просьбе владельца: авто-коррекция (уровни) включена по умолчанию и отключается
галочкой. Ползунки: резкость (0–100), яркость, контраст, насыщенность (−50…50), поля вокруг
вещи (0–20%), переключатель тени, кнопка «Сбросить». Настройки запоминаются в
`localStorage` телефона (`src/lib/studioSettings.ts`), при изменении превью пересобирается
из уже вырезанной вещи без повторного запуска модели. Коррекция — `adjust()` в
`src/lib/imageOps.ts`. Проверено в Chromium: яркость и поля меняют результат.

Страница раздаётся самим Convex (`/studio`, `/assets/*`, `scripts/publish-studio.sh`), Vercel
не используется.
